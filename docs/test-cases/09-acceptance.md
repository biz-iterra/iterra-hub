# 受入テスト仕様（UAT）

プロダクトオーナーが「業務として使えるか」を実操作で判定する。機能単位の合否はシステムテスト（03〜07）で
担保済みという前提に立ち、ここでは**業務シナリオの完遂**だけを見る。

- 実施環境: ステージング、または本番デプロイ直後の検証ウィンドウ（本番で実施した場合、作成データは必ず論理削除まで行う）
- 実施タイミング: 新機能・仕様変更・UI 刷新を含むリリースの Gate 4（test-strategy.md §4）
- 準備: qa エージェントが該当シナリオの抜粋と手順書・テストデータを用意する
- 記録: 各シナリオの 合格 / 条件付き合格（許容した差異を明記）/ 不合格 を `docs/test-checklist.md` に記録

最終更新: 2026-08-03

## UAT-01 営業メンバーの日次業務（member ロール）

1. ログイン → ダッシュボードで自分の担当状況（KPI・最近のディール・アクティビティ）を把握できる
2. `/leads` で今日架電すべきリードを検索・絞り込みで特定できる
3. 架電結果を社内対応として記録し、温度・ステータスを更新できる
4. 記録がリード詳細とダッシュボードのアクティビティに反映される
5. 自分の担当外データが見えていないこと（一覧件数の妥当性を目視）

**合格基準:** 一連の操作が画面遷移に迷わず 10 分以内で完了し、記録の反映に齟齬がない。

## UAT-02 名刺取込の月次業務（admin ロール）

1. Eight からエクスポートした実 CSV を `/admin/leads/import` で dry-run する
2. 件数・エラー行・未登録マスタの一覧を見て、取込可否を判断できる
3. commit 後、リード・連絡先・事業者情報が期待どおり作られている
4. 既存事業者と同じ会社の名刺が重複登録されず名寄せされている（法人番号 > ドメイン > 住所+名称 > 名称）
5. `/contacts/cards` で名刺情報を確認できる

**合格基準:** 実データで名寄せ誤り（別会社への統合・同一会社の重複）が発見されない。
発見された場合は件数と内容を記録し不合格とする。

## UAT-03 リードから受注までの一連（manager ロール）

1. 有望リードをディール化（Deal 昇格）する
2. ディールカンバンでステージを進め、金額・クローズ予定日を管理する
3. 受注に伴い契約を登録する
4. 取引先（Account）が自動作成され、ディール・契約・事業者情報・連絡先が相互リンクで辿れる
5. 必要ならプロジェクトを起票し、ディールから辿れる

**合格基準:** リード→契約までの全工程がシステム内で完結し、二重入力・手作業の穴埋めが発生しない。

## UAT-04 マネージャーの週次レビュー（manager ロール)

1. `/progress`（inbound / outbound / inquiry）で流入チャネル別の進捗を確認できる
2. ダッシュボードのファネルと担当者別ディール数が実感と合う
3. `/deals` テーブルビューでパイプライン・ステージ絞り込みと金額集計ができる
4. `/contracts` で当月の契約状況を確認できる

**合格基準:** 週次レビュー会議に必要な数字がスプレッドシートへの転記なしで揃う。

## UAT-05 管理者の運用業務（admin ロール）

1. `/admin/members` でメンバー追加・ロール変更・無効化ができる。無効化したメンバーが担当者候補から消える
2. `/admin` でマスタ（ステータス・ステージ・色）を追加・変更でき、画面のバッジに反映される
3. 誤登録データを論理削除し、`/admin/deleted` から復元できる
4. `/admin/logs` で「誰がいつ何を変更したか」を追跡できる

**合格基準:** 運用マニュアル（`docs/operation-manual.md`）どおりに操作でき、記載との乖離がない。
乖離があればマニュアル修正を起票して条件付き合格とする。

## UAT-06 問い合わせ流入の自動連携

1. コーポレートサイトの問い合わせフォームからテスト送信する
2. D1 経由でリードが自動作成される（`/api/leads/inquiry-sync`）
3. 流入リードに担当者を割り当て、UAT-01 の日次フローに乗せられる

**合格基準:** フォーム送信からリード表示までが運用許容時間内（同期方式に応じて記録）に完了する。
