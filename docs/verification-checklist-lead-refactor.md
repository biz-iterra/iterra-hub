# ブラウザ動作確認チェックリスト — Lead リファクタ一式（2026-04-20）

本日実装した以下の改修を対象にブラウザ上で動作確認を行うチェックリストです。

## 対象改修

| 番号    | 内容                                                                           |
| ------- | ------------------------------------------------------------------------------ |
| Phase 1 | Lead カテゴリ独立化（マスタ M22 新設 / stage slug 'sql'→'sales' / CASE 廃止） |
| ①      | Lead から既存 Company/Contact 紐付け UI を削除                                 |
| ②      | Lead→Opportunity 昇格時の Company/Contact/Account/Deal 自動生成               |
| ③      | サイドメニューを MA/SFA/CRM/管理 で分類                                        |
| ④      | フィルタ・検索の共通コンポーネント化（`/leads` のみ先行適用）                |
| ⑤      | 詳細→編集ページ→保存フロー統一（Lead のみ先行適用）                          |
| ⑥      | キャンペーン紐付けを Campaign 側に集約、Lead 側は参照のみ                      |
| ⑦      | Lead 対応ログ追加ボタンを「架電」→「対応ログを追加」に汎用化                  |

## 3. Opportunity 昇格時の自動生成（②）

### 法人リードの昇格

- [X] 任意の法人リード（account_type=「法人」）の詳細から編集画面へ
- [X] ステージを「Opportunity」に変更 → 保存
- [ ] `/companies` に新 Company が生成されている（company_name はリードの値）
- [ ] `/contacts` に corporate_rep タイプの新 Contact が生成されている
- [ ] `/accounts` に新 Account が生成されている
- [ ] `/deals` に新 Deal が生成されている
- [ ] 新 Company の primary_contact が新 Contact に設定されている
- [ ] 元のリード詳細ページの `promoted_deal_id / promoted_company_id / promoted_contact_id / promoted_account_id` が DB 上で設定されている

### 個人事業主リードの昇格

- [ ] 個人事業主リード（account_type=「個人事業主」）を Opportunity に変更 → 保存
- [ ] `/contacts` に individual タイプの新 Contact が生成されている
- [ ] `/accounts` に新 Account が生成されている
- [ ] `/deals` に新 Deal が生成されている
- [ ] **Company は生成されない**

### 再昇格の抑止

- [ ] 昇格済みリードを一度 Opportunity 以外のステージに戻して再度 Opportunity に変更
- [ ] **新規 Deal / Company / Contact / Account は重複生成されない**（既存のまま）

### エラーケース

- [ ] 必須情報欠落（lead_name 空など）では昇格失敗メッセージが返り、一部だけ生成される中途半端な状態にならない
